Инструкция к песочнице

Эта песочница предназначена для локального тестирования скрипта fetch_backup.js без запуска GitHub Action.

Порядок работы

  • Шаг 1. Загружает предыдущую версию данных из папки data/ для последующего сравнения. Выполняется автоматически при старте.
  • Шаг 2. Получает список городов с API Fandom. (Можно пропустить, если сразу грузить файл на шаге 3).
  • Шаг 3. Собирает частоты и названия станций. Порождает основные файлы.
  • Шаг 4. Обогащает данные (ищет потоки, логотипы, жанры).
  • Шаг 5. Сравнивает старые и новые данные, формирует отчет.

Файлы и их назначение

  • backup-api.json — главная база городов и станций. Формируется на Шаге 3.
  • cities_list.md — простой список городов. Формируется на Шаге 3.
  • stations_groups.json — сгруппированные уникальные названия станций. Нужен для Шага 4. Формируется на Шаге 3.
  • stations_list.md — человекочитаемый список групп станций. Формируется на Шаге 3.
  • stations_data.json — данные о потоках, логотипах и жанрах. Формируется на Шаге 4.
  • backup-api.history.json — история изменений API. Формируется на Шаге 5.

Протаскивание данных через файлы

Если вы не хотите делать долгие запросы к API (Шаги 2-4), вы можете использовать кнопки [File]:

  • На Шаге 3 можно загрузить готовый backup-api.json. Песочница сама извлечет из него города, сформирует группы и списки, а также активирует Шаг 4.
  • На Шаге 4 можно загрузить готовый stations_data.json, чтобы пропустить долгий опрос radio-browser.info.

Все сгенерированные файлы можно скачать прямо из карточек логов (зеленые кнопки в заголовке карточки).
